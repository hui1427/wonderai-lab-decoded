# 2026-11-23 自研 Android 状态页和车载状态服务

## 目标与输入
用户要求独立手机端、车载电脑、控制板及机械结构的自研路径，首轮可验收手机读取车辆标识或电量。读取 `SelfVehicle/README.md`、`docs/PROTOCOL.md`、`phone/`、`vehicle_mock/` 及 RobotLab 项目索引。此前页面与模拟器的 20 项测试重跑通过，见 mock-smoke.log。旧 APK 和解包工程未修改。

## 实现
新增 `SelfVehicle/android/` Android Java 工程，包名 `com.selfvehicle.control`。手工输入车端地址，提供连接、断开、刷新；后台访问 `/api/v1/status`，按返回数据展示标识、电压、电量、模式、服务版本和串口状态。请求错误清除过时状态并重试；模拟服务明确标识为模拟。代码未实现电机和夹爪操作。

新增 `SelfVehicle/vehicle/vehicle_service.py`，提供自行配置车辆 ID 的 HTTP 状态服务。控制板未接入时电压和电量为空、串口状态未接入，POST 命令返回 501。该服务尚未连接真实串口，也未在 Jetson 上运行。

更新 SelfVehicle 的 README、架构、协议和硬件草案，标明实测状态与形式化 clean-room 认证边界。修正已有文档中 Jetson 供电未确认却写死 5V/12V 的描述。硬件方案仍需按实际载板和负载选型。

## 编译与测试
本机 OpenJDK 11.0.8、ECJ 3.32.0、Android SDK Platform 35、Build Tools 35.0.0。构建使用 ECJ -> D8 -> AAPT2 -> zipalign -> apksigner。工具文件 SHA-256 见 sha256.txt。最终 APK `outputs/SelfVehicle-Control.apk` SHA-256 899E31391AC86D735E537F0A0CD68F56DAC0AF55364717BE5ADD44F55064C1D3，v2/v3 签名校验通过、对齐检查通过；Manifest 仅声明 `com.selfvehicle.control.MainActivity` 和 INTERNET 权限。构建日志含 API 35 弃用警告。

JVM 状态客户端测试覆盖地址、有效数据、协议不匹配、缺失标识；车端服务测试覆盖 ID、未接入状态和未实现命令；Java 客户端与 Python 模拟服务联调读取 7000mV/42% 和 8400mV/100%。上述仅是开发机的模拟数据。本机 ADB 无设备，未测试 Android 真机、Jetson、Wi-Fi/热点、STM32 或运动执行。

## 失败与修正
ECJ 3.38 启动时 JVM 版本不匹配；使用兼容 Java 11 的 ECJ 3.32。首次源码编译漏写右括号，修正后测试通过。首次模拟联调中 Python HTTP/1.1 服务报告连接重置，客户端增加 Connection: close 后重测通过。第一次 AAPT2 尝试不带 package 的 Manifest 失败，命令行构建改为在构建目录生成带 package 的临时副本，Gradle 源 Manifest 保持无 package。

## DSH 工具请求
尝试下载用户指定的 dsh-purge 安装脚本时，命令被自动审批拒绝，返回 blocked by policy，未给出更具体原因。本轮未安装该插件，也未应用 DSH 宿主补丁。
