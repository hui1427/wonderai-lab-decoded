# WonderAi Lab 本地分析、修改和重建工作流程

## 使用交付物

`WonderAi-Lab.apk` 是基于用户提供的 WonderAi 1.4.3 制作的本地兼容版。应用名称为 WonderAi Lab，包名为 `local.robotlab.wonderai`。原版包名为 `com.hiwonder.wonderai`。Android 可按两个应用管理，首次启动新版需重新授予权限、选择设备。原工程中的功能实现、指令和资源随包保留；手机启动、两版共存和不同型号机器人联动仍待实测。

在 Windows 上解压工程到较短的路径，例如 `D:\RobotLab`。进入有 `build.cmd` 的目录，修改文件后双击该脚本。每次构建产生 `builds\日期时间\WonderAi-Lab.apk` 和 `build.log`。本机已用 Java 11、Apktool 3.0.3、Android Build Tools 35.0.0 成功执行。工程自带后两者所需的 Windows 工具。其他电脑需要带 `keytool.exe` 的 Java。也可以在项目目录执行下列命令指定 Java。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -JavaExe 'D:\路径\bin\java.exe'
```

首次构建会在当前 Windows 用户的 `%LOCALAPPDATA%\RobotLabWonderAi\signing\` 生成本地开发签名。后续同用户、同电脑使用同一目录即可签名更新。密码通过 Windows DPAPI 保护。私钥未装入工程压缩包。另一台电脑首次构建将生成另一签名，覆盖安装本次交付版本需要相同签名。安装全新兼容版不需要私钥。

## 1　原件取证与输入检查

原件为 `base.apk.1`。按 ZIP/APK 容器读取，无须改名。`logs/input-sha256.txt` 记录 SHA-256，`original-badging.txt`、`original-manifest.txt`、`original-signature.txt` 保存原版身份、权限、页面和签名结果。应用版本为 1.4.3（36），最低 Android API 21，目标 API 36。原包 v1、v2 签名可验证。以下为从头复查的命令，在工程目录执行，把第一行改成原件路径。Python 检查脚本以 3.12 验证。

```powershell
$apk = 'D:\原件\base.apk.1'
$java = 'D:\SIMULIA\EstProducts\2022\win_b64\code\jre\bin\java.exe'
Get-FileHash -Algorithm SHA256 -LiteralPath $apk
.\tools\aapt.exe dump badging $apk
& $java -jar tools/apksigner.jar verify --verbose --print-certs $apk
$env:ROBOTLAB_INPUT_APK = $apk
python analysis/inspectdex.py
python analysis/setters.py
python analysis/check.py
```

前三个 Python 入口分别复查 DEX 中 AES 辅助类、开关构造器及直接调用候选、数据库头和 SQLite 完整性。用于初筛的 DEX 搜索再通过解包后的 Smali 核对。

## 2　识别通信加密和实际数据格式

从 `classes.dex` 追到 `app/smali/com/deng/netlibrary/netLib/utils/AESHelper.smali`。`paramsByAES*` 在开关开启时将参数序列化为 JSON，用 UTF-8 转成字节，经 AES-CBC 和 PKCS#7 填充加密，输出标准 Base64、不换行，放入 JSON-RPC 2.0 请求的 `params`。响应分支处理 `result`。密文中没有前置 IV。加密读取密钥字符串字节，解密显式使用 ASCII，因此双向测试使用 ASCII 密钥。CBC 的 IV 为 16 字节。

`ZyNetHttps$Builder.smali` 的三个构造器将输入、输出加解密开关都初始化为 false。辅助类内置的密钥和 IV 字符串分别仅 8、10 字节，属于无效占位值。保留原有默认值即可复现原程序行为。没有提供真实密文、有效设备密钥或已知明密文对。本次没有解出真实设备数据。证据在 `logs/aes-instructions.txt`、`logs/encryption-defaults.txt` 和 Smali 原文。

附带 `aes.cjs` 可离线加解密序列化后的参数文件。需要 Node.js，调用时由本机环境变量 `ROBOTLAB_AES_KEY`、`ROBOTLAB_AES_IV` 提供有效的原始文本参数。输入 JSON 使用 UTF-8 无 BOM，空格、换行和字段顺序都会影响密文。输出到一个新文件。工具不主动记录输入、口令或明文。

```powershell
node aes.cjs encrypt params.json params.b64
node aes.cjs decrypt params.b64 recovered.json
node test-aes.cjs qdBKRVjL3eXtVjxlZZs5PA==
```

最后一行只用公开的合成测试值，无需环境变量。测试用 .NET 独立计算预期 AES-128 密文，再用 Node.js 对拍；三种密钥长度分别覆盖空数据、中文和整块边界。见 `logs/aes-test.txt`。这项测试验证编码与算法，不能证明真实设备采用了测试密钥。

五个自带 `.db` 文件均可直接用 SQLite 打开。`command` 表行数分别为 AiArm 9、JetHexa 9、JetHexaMode 4、JetHexaROS2 9、JetSpider 9。详情在 `logs/comparison.json`。

## 3　解包和编辑

交付的 `app/` 已解包、已修改。若要从原件重做，在另一个空目录放一份 `tools/`、`analysis/`、`logs/` 及构建脚本，再执行下面三条。`apply_identity.py` 预期输入为原版解包内容，已改过的工程可直接构建。

```powershell
& $java -Xmx2g -jar tools/apktool.jar d $apk -p framework -o app
python analysis/apply_identity.py
python analysis/index_pages.py
```

本次只对五个源文件作有意修改，即 Manifest 包名、`BuildConfig` 应用标识、默认及简繁中文的桌面名称。变更前后文本在 `logs/changes.diff`。业务类继续使用原 Java 命名空间。工程形态为 Apktool 的 XML、Smali、资源和预编译本机库。

| 想改的内容 | 编辑位置及方法 |
|---|---|
| 某个页面的布局 | 用 `pages.csv` 搜索 Activity，再打开 `app/res/layout/布局名.xml`。例如启动页为 `activity_start.xml`。回调和事件在表中对应的 Smali 及同名 `$` 内部类。没有直接引用布局的页面要继续查看父类或动态创建代码。 |
| 中英文文案 | `app/res/values/strings.xml`、`values-zh-rCN/strings.xml`、`values-zh-rTW/strings.xml`。保留现有资源名称和引用。 |
| 设备发现 | `app/smali/com/hiwonder/wonder_ai/connect/Scanner$ScanAsyncTask.smali`。已核对 UDP 本地端口 9025、目的端口 9027、探测文本 `LOBOT_NET_DISCOVER`。同目录 `Scanner.smali` 构造扫描地址。 |
| 运动指令、ROS 消息、心跳 | 搜索 `protocol-literals.csv` 获取页面、文件和行号，继续沿调用查看 `utils/JSONutils.smali`、`connect/JWebSocketClient.smali` 和具体 Activity。例如 `/controller/cmd_vel` 出现在多个机型，修改前先核对目标机型。 |
| 视频、拍照 | 在相关 Activity 搜索 `:8080/stream?topic=`、`:8080/snapshot?topic=` 或 `?action=stream`。路径、主题和尺寸依机型变化。 |
| TCP、UDP、蓝牙 | `connect/TcpSocket.smali`、`connect/UdpClient.smali`、`utils/BluetoothTool/`。指令封装也可能在页面内部类或 `utils/CommandConstant.smali`。 |
| 动作数据库 | `app/assets/*.db`。使用副本编辑，先查询 `sqlite_master` 与 `PRAGMA table_info(command)`，修改后运行 `PRAGMA integrity_check`。既有安装可能从自身数据目录读取已拷贝的数据库。 |

`pages.csv` 保留 Manifest 中 137 条 Activity 声明，对应 136 个类。原包重复声明了 `JetMaxProPositonActivity`。`protocol-literals.csv` 是可检索的代码线索，含路径和拼接片段；二进制命令、动态生成的完整报文和集中式辅助函数需继续从 Smali 查看。

## 4　重建、签名及核验

`build.ps1` 依次组装 DEX 和资源、生成未签名包、执行 zipalign、使用本地证书签名、验证签名和对齐、读取重新打包后的元数据，并保存最终 SHA-256。第一次从 Smali 和 XML 完整编译，第二次复用第一轮的编译缓存并重新封装、签名。每轮使用独立的时间戳目录。`logs/rebuild.log` 包含第二轮命令、时间和输出。原始首轮日志保存在 `logs/first-build.raw.log`，当时两种 PowerShell 输出编码混用，后续构建已统一为 UTF-8。

```powershell
python verify.py $apk 'D:\产物\WonderAi-Lab.apk'
& $java -jar tools/apktool.jar d -r 'D:\产物\WonderAi-Lab.apk' -o recheck
python compare-smali.py app/smali recheck/smali
```

本次比对了 Activity 名单、启动入口、DEX 类及方法引用签名集合、资源 ID 与名称、assets 与本机库逐文件 SHA-256。五个数据库还通过 SQLite 完整性检查。`logs/comparison.json`、`signature.txt`、`alignment.txt`、`smali-roundtrip.json`、`smali-roundtrip.diff` 保存详细结果。独立回读最终包后，6,563 个类全部在场，Smali 文本差异涉及静态字段默认值写法和文本格式，方法指令没有文本差异。签名校验器对传统 v1 JAR 签名未覆盖的部分 META-INF 元数据给出警告；同包 v2、v3 整包签名通过。修改任何最终 APK 内容后须重新签名。

## 5　设备端验收与记录

本次未检测到可供测试的 Android 设备或已运行的模拟器，未连接机器人。每次实测应记录手机型号、Android 版本、机器人型号和固件、APK 哈希、页面、操作、期望结果及实际结果。在 `pages.csv` 对应页面填写实测状态，可另存带日期的副本。优先执行以下顺序。

1. 保留原版，安装 WonderAi Lab，确认桌面有两个独立入口；分别启动，记录首页、权限和机型列表。
2. 让手机加入目标机器人网络，记录发现结果。先比较原版和新版能否发现同一设备，再进入同一功能页。
3. 先验证状态读取、视频和拍照。运动测试在安全工位对照原版验证方向、速度、松手停止、退出和断连。机械臂和动作组逐个测试起止姿态与反馈。
4. 按实际设备支持的页面继续测试，记录适用性。遇到差异，保留页面和操作时间、脱敏后的日志或报文，回 `pages.csv` 定位代码。屏幕可打开和设备完成动作要分别记录。

## 6　工具来源、异常与记录范围

工具来源为 Maven Central 的 `org.apktool:apktool-cli:3.0.3` 及 Google 的 `build-tools_r35_windows.zip`。Apktool JAR 与 Maven 仓库公布的 SHA-1 一致；实际交付工具的 SHA-256 在 `logs/tool-hashes.csv`。Java 使用机器已有的 OpenJDK 11.0.8，未修改系统 Java 配置。参考 [Apktool 安装说明](https://apktool.org/docs/install/) 与 [Android apksigner 文档](https://developer.android.com/tools/apksigner)。

前期先用 ZIP、DEX 字符串和临时字节码读取脚本定位 AES，发现数据库均为 SQLite。一次 Python 临时调用因推导式赋值语法错误而失败，随后改为循环重新执行。获取 Apktool 时，GitHub 的直连重置、API 下载超时或被限流，Bitbucket 下载亦未成功，最终采用 Maven Central 完整 JAR。Android Build Tools 下载另外用分段请求获得完整副本。前期探索为事后整理，关键检查已重跑落盘；解包、构建、签名及交付包核验保留工具输出。没有采集或记录手机通信内容及签名密码。
